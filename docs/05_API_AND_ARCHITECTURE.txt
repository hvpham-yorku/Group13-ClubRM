2. AUTHENTICATION FLOW
================================================================================

LOGIN FLOW:
1. User submits email/password
2. Backend validates credentials
3. Backend generates JWT (access token + refresh token)
4. Frontend stores tokens (httpOnly cookie for refresh, memory for access)
5. Frontend includes access token in Authorization header for all requests

TOKEN STRUCTURE:
{
  "sub": "user_id",
  "email": "user@example.com",
  "org": "organization_id",
  "term": "term_id",
  "role": "role_id",
  "permissions": ["tasks.read", "tasks.write", ...],
  "iat": 1706745600,
  "exp": 1706749200
}

API HEADERS (Every Request):
Authorization: Bearer <access_token>
X-Organization-Id: <organization_id>  (for multi-org users)
X-Term-Id: <term_id>  (optional, defaults to active term)

CONTEXT SWITCHING:
- When user switches org/term, frontend calls POST /api/auth/switch-context
- Backend issues new JWT with updated org/term/role/permissions
- Frontend updates stored token and reloads dashboard

3.2.1 DASHBOARD INSIGHT ENDPOINTS (Expandable Tile Deep-Dives)
-------------------------------------------------------------------------------

These endpoints are called on-demand when a user clicks a dashboard tile
to expand it. They return detailed analytics, diagnostics, and recommendations.
Not called on initial dashboard load to keep the main view fast.

GET /api/v1/dashboard/{role}/insights/health
  Permission: dashboard.view
  Query: org_id, term_id
  Response: {
    overallScore: number,
    previousScore: number,
    trend: [{ label, value }],
    breakdowns: [{
      category: string,
      score: number,
      maxScore: number,
      status: 'good' | 'warning' | 'critical',
      insights: [{ label, status, detail }]
    }],
    topStrengths: string[],
    topConcerns: string[]
  }
  Backend: Composite score from 4 pillars (members, events, budget, tasks),
           each querying respective tables and comparing to thresholds.

GET /api/v1/dashboard/{role}/insights/members
  Permission: members.read
  Query: org_id, term_id
  Response: {
    totalMembers, activeMembers, newThisTerm, retentionRate,
    avgTasksCompleted, avgEventsAttended,
    recentJoiners: [{ name, role, department, joinDate }],
    byDepartment: [{ label, count, percentage }],
    byYear: [{ label, count, percentage }],
    byRole: [{ label, count, percentage }],
    inactiveWarnings: [{ name, lastActive, reason }]
  }
  Backend: Aggregates memberships JOIN users. Retention = members active
           both current and previous term / previous term total.
           Inactive = no task completions or event attendance in 14+ days.

GET /api/v1/dashboard/{role}/insights/budget
  Permission: budget.read
  Query: org_id, term_id
  Response: {
    totalBudget, spent, remaining, percentRemaining,
    burnRate, targetBurnRate, projectedRunway,
    monthlySpend: [{ label, value }],
    categories: [{ name, allocated, spent, status }],
    biggestExpenses: [{ description, amount, date, category }],
    alerts: [{ label, status, detail }]
  }
  Backend: Reads budgets + budget_categories + expenses.
           burn_rate = spent / months_elapsed. Alerts auto-generated
           from threshold comparisons.

GET /api/v1/dashboard/{role}/insights/events
  Permission: events.read
  Query: org_id, term_id
  Response: {
    totalUpcoming, avgRegistrationRate, volunteerCoverageRate,
    events: [{
      title, date, registered, capacity,
      volunteersFilled, volunteersNeeded,
      status: 'on_track' | 'at_risk' | 'critical',
      risks: string[]
    }],
    trend: [{ label, value }],
    strengths: string[],
    concerns: string[]
  }
  Backend: events + event_registrations + event_volunteers.
           Status auto-assigned: critical if <50% reg within 7 days,
           at_risk if <70% within 14 days.

GET /api/v1/dashboard/{role}/insights/risks
  Permission: dashboard.view
  Query: org_id, term_id
  Response: {
    totalRisks, highCount, mediumCount, lowCount,
    resolvedThisWeek, trendingUp: boolean,
    risks: [{
      title, category, severity, description,
      recommendation, affectedEntity, detectedAt
    }]
  }
  Backend: Aggregated from budget alerts, overdue tasks, event risk
           flags, and member inactivity scans. Runs every 5 min via
           background job writing to dashboard_metrics.

GET /api/v1/dashboard/{role}/insights/approvals
  Permission: dashboard.view
  Query: org_id, term_id
  Response: {
    totalPending, avgWaitDays, oldestItem,
    byType: [{ type, count }],
    items: [{
      id, type, title, submittedBy, submittedAt,
      daysWaiting, priority, amount?, description
    }],
    recentlyApproved: [{ title, approvedAt, type }]
  }
  Backend: Unions events(pending_approval) + expenses(pending) +
           posts(pending_approval). Priority auto-set by amount
           thresholds and event proximity.

4. ERROR HANDLING
================================================================================

STANDARD ERROR RESPONSE:
{
  "error": {
    "code": "PERMISSION_DENIED",
    "message": "You do not have permission to perform this action",
    "details": {}
  }
}

ERROR CODES:
- UNAUTHORIZED (401): Missing or invalid token
- PERMISSION_DENIED (403): Valid token but insufficient permissions
- NOT_FOUND (404): Resource not found
- VALIDATION_ERROR (400): Invalid request data
- CONFLICT (409): Resource conflict (duplicate, etc.)
- RATE_LIMITED (429): Too many requests
- SERVER_ERROR (500): Internal server error

API SERVICE (axios wrapper):

// services/api.ts
import axios from 'axios';

const api = axios.create({
  baseURL: process.env.REACT_APP_API_URL,
  headers: { 'Content-Type': 'application/json' }
});

// Request interceptor - add auth token
api.interceptors.request.use((config) => {
  const token = getAccessToken();
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  const context = getContext();
  if (context.organizationId) {
    config.headers['X-Organization-Id'] = context.organizationId;
  }
  return config;
});

// Response interceptor - handle token refresh
api.interceptors.response.use(
  (response) => response,
  async (error) => {
    if (error.response?.status === 401) {
      const refreshed = await refreshToken();
      if (refreshed) {
        return api.request(error.config);
      }
      logout();
    }
    return Promise.reject(error);
  }
);

export default api;

6. REAL-TIME UPDATES (WebSocket)
================================================================================

WEBSOCKET EVENTS:

Connection: ws://api.clubrm.com/ws?token={jwt}

SERVER -> CLIENT EVENTS:
- notification:new - New notification
- task:updated - Task status changed
- event:updated - Event status changed
- approval:new - New approval needed
- member:joined - New member joined org

CLIENT -> SERVER EVENTS:
- subscribe:org - Subscribe to org updates
- unsubscribe:org - Unsubscribe from org
- ping - Keep alive

FRONTEND INTEGRATION:

// hooks/useWebSocket.ts
import { useEffect } from 'react';
import { useQueryClient } from '@tanstack/react-query';

export const useWebSocket = () => {
  const queryClient = useQueryClient();
  const { token, context } = useAuth();
  
  useEffect(() => {
    const ws = new WebSocket(`${WS_URL}?token=${token}`);
    
    ws.onopen = () => {
      ws.send(JSON.stringify({ type: 'subscribe:org', orgId: context.organizationId }));
    };
    
    ws.onmessage = (event) => {
      const data = JSON.parse(event.data);
      
      switch (data.type) {
        case 'notification:new':
          queryClient.invalidateQueries(['notifications']);
          break;
        case 'task:updated':
          queryClient.invalidateQueries(['tasks']);
          queryClient.invalidateQueries(['dashboard']);
          break;
        // ... handle other events
      }
    };
    
    return () => ws.close();
  }, [token, context.organizationId]);
};
